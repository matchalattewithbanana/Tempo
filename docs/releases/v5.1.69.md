# Tempo 5.1.69 — Stable

**Channel:** Stable · **Android:** 8.0+ · **Package:** `me.avinas.tempo` · **Version code:** 4823

Tempo 5.1.69 promotes the 5.1.69 beta line after a broad reliability, import, tracking, performance and Material 3 Expressive cleanup. Android, Chromium and Firefox are published from the same validated source commit.

## Highlights

### Tracking and listening reliability
- Removed blocking shutdown persistence from the tracking service and moved active-session durability into a dedicated journal/recovery boundary.
- Isolated Android MediaSession registration, token replacement and callback lifecycle from Tempo's tracking policy.
- Centralized MediaSession content classification, local artwork persistence and playback identity keys.
- Improved recovery behavior so clean shutdown is acknowledged only after durable state is known to be safe.

### Import, restore and data integrity
- Hardened Tempo ZIP parsing and reject ambiguous duplicate core payload entries.
- Stream large restore histories through a bounded staging store rather than keeping unbounded import data in memory.
- Keep Room database restore atomic while isolating profile, appearance and cache follow-up work with explicit partial-restore warnings.
- Centralized listening-event reconciliation and source-authority decisions to reduce duplicate or lower-quality overlapping events.
- Preserve conservative behavior for uncertain legacy/scrobble overlaps rather than silently deleting legitimate repeat plays.

### Performance and architecture
- Reduced large orchestration classes across tracking, Home, Settings, Stats and import/restore.
- Split the statistics DAO into focused Room query families while preserving one `StatsDao` API and the existing database contract.
- Moved Home dashboard fan-out and chart shaping behind focused loaders/processors.
- Removed Settings polling/platform-status responsibilities from the screen layer.
- Decomposed oversized interactive UI modules including Song/Artist/Album details, Supported Apps, Daily Overview, restore flows, Spotlight, share cards, Desktop Link, Last.fm import and the YouTube Takeout tutorial.

### Material 3 Expressive and personalization
- Standardized adaptive layout behavior around Material compact/medium/expanded breakpoints.
- Bottom navigation remains on compact widths, medium widths use a collapsed wide rail, and expanded widths use the expanded rail state.
- Profile uses native centered Material app-bar chrome.
- Routine app cards resolve to Material tonal surface roles instead of maintaining a parallel translucent-glass design system.
- Appearance Studio now previews Home, Stats and Profile roles and supports touch reordering with accessible button fallbacks.
- Improved phone Settings layout so category cards stay full-width on compact screens and only form columns from the medium breakpoint.

### Browser companion
- Chromium and Firefox companion packages ship with the same Tempo 5.1.69 display version.
- Browser internal manifest version is `5.1.69.1`, preserving upgrade ordering after the beta's `.0` build.
- Release validation typechecks, builds and smoke-tests both browser targets before publication.

## Upgrade notes

Back up Tempo before installing an update. In-place Android upgrades require the same package and signing certificate as the installed build. Do not uninstall solely to work around a signing mismatch unless your listening history has been safely exported.

Google Drive/OAuth behavior still depends on the configured client and release-signing identity. Background playback behavior can also vary with Android vendor power policies. Automated release gates reduce regression risk but do not replace real-device validation across every device/player combination.
