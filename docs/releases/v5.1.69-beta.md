# Tempo 5.1.69 Beta — Import integrity and expressive UI release candidate

**Channel:** Beta / prerelease · **Prepared:** 21 November 2026 · **Base:** `v4.10.25-beta`.

Tempo 5.1.69 Beta is a coordinated Android + Chromium/Firefox companion test release. The version follows Tempo's existing commit-count rollover: `4.10.25` + **244 commits after the previous published beta** (measured before release-metadata preparation) = `4.10.269` → `5.1.69`. This major-number rollover reflects the repository's established numeric scheme, not a claim that all planned 5.x features are complete.

## Changes since 4.10.25 Beta

### Import, backup and listening-data accuracy
- Centralized fingerprint and playback-interval reconciliation checks the **active Room database** while importing Spotify JSON/API, Apple Music, Deezer, Last.fm, YouTube Music, Musicolet, extension playback, and Tempo ZIP backups.
- Better duplicate recognition between Spotify's minute-precision account-history export and Extended Streaming History; Extended History UTC `ts` indicates playback **end** and `ms_played` is actual measured milliseconds.
- More reliable overlapping backup imports: re-map old track IDs and recompute fingerprints, compare compatible track identities across import batches, preserve genuinely missing history and live higher-authority observations.
- Corrected an alias-bridging case where two different provider recordings sharing a title and artist might otherwise have been incorrectly merged via a third track with missing identifiers.
- Google Drive/local backup restore now distinguishes **Skip Duplicates** from **Replace Existing**, with new / replaced / skipped listening counts and more consistent handling of supported app preferences, profile, badges and level.
- YouTube and Musicolet per-event error recovery now use transactional deduplication rather than raw inserts.
- Import summaries distinguish net-new plays from authority replacements; imports update cached stats when they improve existing observations.
- New read-only exact-fingerprint duplicate audit and opt-in, backup-confirmed cleanup in Settings. **Ambiguous older records are never automatically erased.**

### Material 3 Expressive, appearance and responsiveness
- Further Material 3 Expressive theme, surface, navigation, color, motion and accessibility refinements across Home, Stats, History, Profile, Settings, Appearance, Backup/Restore and shared music tiles.
- Readable themed History/Insights badges and Profile labels; Stats search keyboard focus no longer waits a fixed 280ms.
- Theme-specific color-pairing fixes for Light/Dark/OLED/custom appearances, adaptive effects and reduced-motion handling.
- Performance-oriented lazy Settings/Backup sections, reduced unnecessary animations, coherent cached-stat updates and more responsive search behavior.
- Prepublication Kotlin compile fixes for shared decorative shapes, artwork accent helpers, Settings navigation layout, onboarding canvas colors, Stats icons/motion handling and History/detail UI.

### Browser companion
- Chromium and Firefox companion builds share the Android display version. Metadata uses `5.1.69-beta`; browser manifest numeric version is `5.1.69.0`.

## Version and update compatibility

- **Android:** `me.avinas.tempo`, versionName `5.1.69-beta`, versionCode **4822**, Android 8.0+.
- **Browser:** Chromium + Firefox ZIPs with `5.1.69-beta` display version.
- **Signing:** The release workflow must verify that the APK matches the established beta signing certificate; never substitute an ephemeral debug signer.
- **Install safely:** Export a local Tempo backup before updating. To preserve listening data, **do not uninstall an existing installation** to work around a signing mismatch. Retain your backed-up ZIP before testing overlapping restores.

## Beta testing and known limitations

This is **not yet a stable sign-off**. Physical-device testing remains needed for Google account/Drive authentication, large overlapping real-world imports, background tracking across device power policies, performance and memory on old phones, Material 3 Expressive in Light/Dark/OLED and large fonts, accessibility focus, adaptive layouts, widgets and sharing.

Deduplication is conservative: Last.fm scrobbles or reconstructed listening counts may not contain enough evidence to prove an overlap with measured Spotify play intervals. Distinct live device sessions, quick consecutive replays, and uncertain legacy data are intentionally preserved rather than silently merged/deleted. Report **before/after total listening minutes and plays**, import sources and timestamp ranges when reporting an inflation problem.
